The C-variadic type `...` has been written in an invalid context.

Erroneous code examples:

```compile_fail,E0743
type Type = ...; // error
```

```compile_fail,E0743
unsafe extern "C" fn function(x: u8, y: &...) {} // error
```

Syntactically speaking, `...` is only allowed as the type of function parameters.

In the second example, while `...` does appear *in* the type of a function parameter as part of the
`&...`, it's not *the* type of the function parameter and thus not allowed either.

---

A function or function pointer type whose last parameter is syntactically of type `...` and which
has a compatible calling convention (e.g., `C`) is considered to take a variable number of arguments
enabling you to bidirectionally interface with variadic C functions (like `printf`). Semantically
speaking, such parameters end up being of type [`core::ffi::VaList<'_>`].

Thefore it doesn't make sense to use `...` in any other type context.

[`core::ffi::VaList<'_>`]: https://doc.rust-lang.org/stable/core/ffi/struct.VaList.html
